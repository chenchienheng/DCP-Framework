# Internal Relational Mesh — Relation Primitive Reference

> Lifecycle: `PUBLIC_RESEARCH_REFERENCE`
> Runtime: `false`
> Authority: `none`

This file preserves the useful idea that complex relations may be non-linear, overlapping, layered, crossed, partially recoverable and context-dependent. It does not establish a fixed CoreTri mesh, five-axis mapping, master chain, review axis, or register topology.

## Retained primitives
- relations need not form a simple hierarchy or linear chain;
- multiple valid entry points may exist when stable identity and position/context remain resolvable;
- curved/overlapping/crossed relations require explicit dependency, boundary, evidence and affected-scope handling;
- failure in one relation should preserve original evidence/context and invalidate only the affected branch where possible;
- return/reconciliation should target the accountable receiver, not a fixed central register.

## Topology rule
Spherical/topological language may be used as a reasoning representation for non-central, multi-entry relation space. It is not a claim that the runtime literally has one permanent spherical topology or that every subject must be mapped through the same structure.

`Topology representation != World truth`
`Relation density != Authority`
`Shared mesh != Central control plane`
`Return path != Master-chain writeback`

## Retired assumptions
- mandatory AXIS-01 through AXIS-05 mapping;
- `consistent triad` as universal acceptance authority;
- `return_failed -> AXIS-05`;
- successful relations must be written to unified tracking registers;
- missing coordinates inside old axes are present-day architecture gaps.
