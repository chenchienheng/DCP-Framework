## 人話 / Human zh-TW

本頁不再是必要的分類骨架，也不是 Reader 必讀層。它只保留一組在特定 affected cone 有用的 dispatch questions。

DCP 現行先判 Stable Existence 與生命鏈，再視需要套用以下 view：Domain／Authority／State／Circle／Pole／Cloud。若某一軸沒有 material effect，就不必填；沒有固定順序，也不得把六軸變成六層資料夾、六個永久分類或六個 ontology organ。

GitHub、Drive、DB、SaaS、Local、CAD/BIM/3D、Spreadsheet、Media、Code、Binary、API、Issue/PR/Branch 等都只是 carrier／representation 家族。副檔名或載體差異不建立新 Identity。

固定：

`Stable Existence before Dispatch View`  
`Extension ≠ Taxonomy`  
`Folder ≠ Ontology`  
`Cloud/Carrier ≠ Identity/Authority`

六個問題在需要時可問：
- Domain — 原生世界／Owner／Source domain 在哪裡？
- Authority — 誰能讀、判、寫、批准、釋放、ACK？
- State — 現在生命狀態為何？
- Circle — 本次 affected scope／Project／Window／Review 邊界為何？
- Pole — 哪個 CoreTri Native Pole 需要 bounded projection？
- Cloud — 此次由哪個 carrier 承載表徵？

Dependency、Evidence、Return、Reconciliation、Re-entry、Rebuild 是 primary governed relations，不是為了湊分類而新增的 storage dimensions。

## Professional English

This page is retained only as an optional compatibility/dispatch view. It is not a mandatory ontology or reader layer. Stable existence and lifecycle relations are primary. Domain, Authority, State, Circle, Pole and Cloud may be used as bounded questions only when material; no fixed order is required. File extensions, folders, repositories and carrier families do not define identity or architectural truth.
