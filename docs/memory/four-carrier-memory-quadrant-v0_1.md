# Four-Carrier Memory Quadrant v0.1

Status: Candidate / Memory Carrier Governance / No Runtime / No External Writeback
Use As: candidate design for long-chain return, archive, rebuild, and pollution control across cloud carriers
Do Not Use As: approved doctrine, storage migration approval, backup policy, company retention policy, or external writeback authorization

## Core

A return packet should not become endless storage noise. It should have time, essence, contamination control, retention class, and rebuild hooks.

The memory network should use multiple carriers by role, not dump every artifact into Google Drive.

```yaml
Memory_Carrier_Principle:
  GitHub: "canonical chain / versioned governance / hook anchors"
  Google_Drive: "human-readable current returns / daily-weekly circulation"
  Box_or_Dropbox: "cold archive / heavy artifact quarantine / historical deposits"
  OneDrive_or_iCloud: "personal operating memory / device-side continuity / private human-base bridge"
```

## Four Quadrants

```yaml
Memory_Quadrants:
  Q1_Current_Working_Memory:
    carrier: "Google Drive"
    purpose:
      - "daily returns"
      - "weekly integration"
      - "decision queue"
      - "human-readable logs"
    retention: "short to medium"
    risk: "overcrowding / duplicate current state"

  Q2_Canonical_Version_Memory:
    carrier: "GitHub"
    purpose:
      - "repo-safe candidate files"
      - "red doors"
      - "registries"
      - "issue / PR history"
      - "hook anchors"
    retention: "long"
    risk: "candidate mistaken as approved"

  Q3_Cold_Archive_Memory:
    carrier: "Box / Dropbox candidate"
    purpose:
      - "superseded packets"
      - "large archives"
      - "old source bundles"
      - "quarantined material"
    retention: "long / dormant"
    risk: "archive pollution returns to mainline"

  Q4_Private_Human_Base_Memory:
    carrier: "OneDrive / iCloud candidate"
    purpose:
      - "personal non-public continuity"
      - "device-adjacent human base"
      - "private field notes"
      - "not for Open Core"
    retention: "personal / controlled"
    risk: "private context leaks into public chain"
```

## Human-Like Memory Pattern

```yaml
Memory_Behavior:
  remember_main:
    - "canonical owner"
    - "latest valid return"
    - "decision queue"
    - "active red doors"
  forget_or_suppress_secondary:
    - "old drafts"
    - "duplicate text"
    - "superseded packets"
    - "non-active logs"
  retrieve_when_needed:
    - "historical disputes"
    - "lineage verification"
    - "source conflict"
    - "rebuild after drift"
```

## Red Doors

- Archive != Deletion.
- Suppression != Denial.
- Cold Archive != Active Source.
- Google Drive File != Mainline Truth.
- GitHub Candidate != Approved Doctrine.
- Private Human-Base != Public Core.
- Retrieval != Promotion.

## Final Rule

Memory should be layered: current returns stay readable, canonical rules stay versioned, old material goes cold, and private context stays bounded. GitHub holds the chain; other carriers hold role-specific memory.
