# Tri-Repo Chain Ecology Health Audit v0.1

Status: Candidate / Health Audit / No Runtime / No External Writeback
Use As: QHA audit matrix for checking whether the tri-repo network is a real circulating chain ecology
Do Not Use As: approved doctrine, merge approval, public release, runtime status, or closeout

## Core

A chain ecology is not proven by having many files. It is proven when each repo knows its role, active files, boundaries, next readers, return paths, red doors, and output candidates.

## Gap Types

```yaml
Gap_Types:
  Missing_Link:
    meaning: "no reads_from or continues_from"
  Missing_Return:
    meaning: "no next_reader or write_to"
  Role_Drift:
    meaning: "repo or LOR acting outside role"
  Boundary_Drift:
    meaning: "private, company, field, or output layers mixed"
  Version_Drift:
    meaning: "old files competing with active files"
  Output_Drift:
    meaning: "candidate modules treated as release"
```

## Red Doors

- Many Files != Chain Ecology.
- Repo Alignment != Cleanup Complete.
- Active Pointer != Approved Truth.
- Output Candidate != Public Release.
- LOR Role != Final Authority.
- Health Audit != Closeout.

## Final Rule

QHA should audit the chain by movement and boundaries, not by file count.
