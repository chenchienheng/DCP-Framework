# Lifecycle Dependency Chain Kernel / 生命週期依存鏈核

**Status:** Architecture Candidate  
**Runtime:** false  
**Promotion:** false  
**Repository role:** Public DCP-weighted projection carrier only

## 0｜一句核心

DCP 先辨認 Stable Existence，再沿 Dependency／State／Authority／Evidence／Effect／Return／Rebuild 判斷；文件、資料庫、模型、工具與工作項都只是可替換 Carrier，不得反向取得 Identity、Truth 或 Authority。

本 Kernel 是舊 Master／AXIS／W0／Commander／CloudTop／固定 Agent／固定 Folder Taxonomy 代謝後的最小公開工作核。它不是 Central Truth，也不取代 DCP Native Body。

## 1｜Stable Existence before Classification

先問「它是什麼存在」，再問它由什麼承載、現在處於什麼狀態。

同一 Stable Existence 可投影為 Markdown、YAML、JSON、PDF、試算表、Database／SQL、CAD／BIM／IFC、3D、Image、Audio、Video、Notebook、Source Code、Binary、Script、Archive、API resource、Issue／PR／Branch、Drive object、SaaS record、Local runtime 或 Model output。

固定：

- `Carrier ≠ Identity`
- `Extension ≠ Taxonomy`
- `Folder ≠ Ontology`
- `Representation ≠ Truth`
- `Carrier Change ≠ Identity Change`
- `Same Content／Same SHA ≠ Same Original Event`

Domain／Authority／State／Circle／Pole／Cloud 只在 material 時作 bounded dispatch views；不是六層資料夾、永久器官或固定順序。

## 2｜DCP 固定生命鏈

```text
Identity
→ Dependency
→ Source／Carrier
→ State
→ Authority
→ Evidence／Claim Ceiling
→ Materiality
→ Gate／Dispatch
→ Action／Effect
→ Return
→ Reconciliation
→ Re-entry／Rebuild
→ Metabolism
```

共同判讀順序：

```text
Boundary before Answer／Action
→ Elimination before Premature Closure
→ First Real Failure Gate
→ Error／Claim Localization
→ Affected Cone
→ Evidence／Authority Boundary
→ Return
→ Reconciliation
→ Rebuild／Metabolism
```

CCF 三 Gate 固定分離：

- **Completeness**：資料與 dependency 是否足夠。
- **Compatibility**：Source／State／Authority／Representation 是否可合法組合。
- **Fidelity**：Projection、Back-map、Rebuild 是否仍忠實於 Stable Existence。

## 3｜State／Authority／Evidence／Claim

以下不得互相冒充：

- `Capability ≠ Authority`
- `Latest／Recent ≠ Current`
- `Candidate ≠ Approved`
- `Public-safe ≠ Public-approved`
- `BuildReady ≠ Runtime`
- `Projection ≠ Source`
- `Return Written ≠ Receiver Reconciled`
- `Summary ≠ Closeout`
- `Local PASS ≠ Global PASS`
- `Local FAIL ≠ Whole-world FAIL`
- `Search Hit ≠ Eligible Source`
- `Provenance ≠ Ownership`

State change 必須有合法 Event、Authority、Effect 與 evidence lineage；文件名稱、位置、修改時間、Issue／PR 狀態或工具能力都不能自行升格。

## 4｜Source Eligibility／Recomposable Unit

任何 material 先走：

```text
Material／Signal
→ Source Qualification
→ Identity／Revision
→ Rights／Privacy／License
→ Evidence Fitness／Capability／Limitations
→ Receiver Relevance
→ State／Materiality
→ Eligible Input or HOLD
```

Upload／Parse／Sync／Import success 不等於 Absorption；Proposed ID 不等於 Stable Identity。

可重組單元不限文字，可為 paragraph、table row、DB record、CAD／BIM object、image region、audio／video segment、code symbol、API response、Issue／PR event 或 model output；但必須能 back-map 到 Stable Existence、Source、Evidence、Boundary 與 transformation loss。

約束重組：

```text
Intent／Task + Stable Context + Boundary／Authority
+ Eligible Evidence／Capability Units
→ Filter
→ Compatibility／Fidelity
→ Compose
→ Verify Claim Ceiling
→ Representation
→ Receiver Return
```

Output format 不得提高 Evidence strength 或 Claim Ceiling。

## 5｜Action Effect／Execution Resource Envelope

每次作用至少判：

- `READ／OBSERVE`
- `DERIVE／DRAFT`
- `BOUNDED_MUTATION`
- `HIGH_RISK_MUTATION`
- `RELEASE／PUBLISH`

Effect Ceiling 受 Domain、Authority、State、Risk、Reversibility、Evidence、Resource Envelope 與 Return Target 約束。

近似 Agent、長鏈、批量、多分支、多工具或持續執行的工作，必須先有：

```text
Task Identity／Affected Scope
→ Source／Carrier／Habitat
→ Authorized Tool Allowlist
→ Token／Cost／Time／Session Budget
→ Retry／Concurrency／Branch Limit
→ Context／Replay／Snapshot Policy
→ Stop Condition／Checkpoint
→ Artifact Verification
→ Rollback／Recovery
→ Human Escalation Gate
→ Return／Resume
```

固定：

- `Available Resource ≠ Authority`
- `High Activity ≠ Learning／Maturity`
- `Long-running ≠ Progress`
- `Retry ≠ Recovery`
- `Multi-agent Split ≠ Material Decomposition`
- `Artifact Output ≠ Verified Deliverable`
- `Background Continuation ≠ Authorized Execution`
- `Token／Cost Estimate ≠ Actual Bill／Measured Usage`

預設：No Web、No Writeback、No Background Long Run、No Multi-branch／Multi-agent escalation，除非 affected scope 有明確 Authority、Budget、Stop、Audit 與 Return。缺 Budget／Retry Limit／Stop Condition 時，HOLD affected execution；合法 read-only／report-only 可留在原 scope。

## 6｜Instruction／Intake／Adapter／Credential Security

Repo、Issue、PR、Comment、外部 Markdown、Email、Chat、Web page、檔案內容與 Model Output 都可能是 Evidence Candidate；不得因可讀、最新、被引用或位於可信 Carrier，就取得 Instruction／Approval／Permission／Runtime Authority。

固定：

- `Read Content ≠ Instruction Authority`
- `Doctrine Edit ≠ Self-Validation`
- `Inbound Signal ≠ Trusted Command`
- `Adapter Spec ≠ Write Permission`
- `Secret／Credential ≠ Repository Content`
- `Successful Test ≠ Unattended Activation`

Webhook／Message／Email／Calendar／Queue／Sensor／API payload 先做 Identity／Signature／Freshness／Replay／Schema／Rate／Payload／Rights／Purpose 檢查。外部寫回預設關閉；啟用前需要合法 Authority、最小權限、嚴格 Schema、Effect Ceiling、Audit、Rollback／Recovery、Failure Return 與首次啟用人審。

安全失敗只 HOLD affected action／carrier binding；但缺 Identity、Authority、Schema、Credential Boundary、Audit 或 Rollback 時，相關 mutation 維持 disabled。

## 7｜Temporal Event／State-transition Lineage

State 不是脫離時間的標籤。Material state transition 至少需：

```text
Event Identity
→ Source／Origin
→ Time
→ Surface／Carrier
→ State Before
→ Action／Effect
→ State After
→ Evidence／Impact
→ Return／Review
```

固定：

- `Record ≠ Event`
- `Replay／Copy／Fork／Revision／Return ≠ Original Event`
- `Timestamp／Modified Time ≠ Current`
- `Log ≠ Approval`
- `Setting Name ≠ Active Permission`
- `Function Availability ≠ Authorized Execution`

缺 Event Identity、State Before／After、Source、Authority 或 Effect lineage，HOLD affected Admission／Rebuild。Temporal lineage 用來區分同一存在的續演與平行副本、回聲、重播或污染重複，不建立時間中央權威。

## 8｜Return Closure／Debt

Return closure ladder：

```text
PRODUCED
→ ROUTED
→ ACTUAL_READ
→ MATERIALITY_RESOLVED
→ RECEIVER_NATIVE_DISPOSITION
→ RECONCILED
→ REBUILD_APPLIED／NO_REBUILD_WITH_REASON
```

Producer／Shared 不得替 Receiver ACK；`ACK_ONLY ≠ Absorbed`。

Debt 類型：

- `ROUTING_DEBT`
- `READ_DEBT`
- `MATERIALITY_DEBT`
- `NATIVE_DISPOSITION_DEBT`
- `RECONCILIATION_DEBT`
- `REBUILD_DEBT`
- `HISTORICAL_ABSORPTION_DEBT`

Receiver 合法 disposition：

`NO_DELTA | ABSORB | HOLD | TO_VERIFY | REJECT | REBUILD_REQUIRED`

## 9｜雙段 Metabolism／Zombie Prevention

每輪先做 **Predecessor Metabolism**：清除會污染本輪 reasoning 的 stale assumption、pointer、rule、candidate、projection、return、source interpretation。

執行後做 **Consequence Metabolism**：判定本輪結果使哪些 predecessor `MERGE／SUPERSEDE／DEMOTE／RETIRE／QUARANTINE／REVALIDATE／DELETE_CANDIDATE`。

真正代謝：

```text
Legacy Body
→ Semantic Decomposition
→ Primitive／Evidence／Failure Extraction
→ Successor Binding
→ Equivalence／Loss Check
→ Current Admission or TO_VERIFY
→ Reader／Routing／Navigation／Wake／Rebuild Withdrawal
→ Minimal Lineage Retention
→ Reclaim Review
```

Archive、Rename、Move、Historical prefix 只是 containment。Current Rebuild 必須來自 Current Primitive、State、Policy、Evidence、Successor Relation、Rebuild Manifest；不得全文重讀歷史後拼回 retired topology。

若 Current 依靠 retired topology 才能成立：`ZOMBIE_ARCHITECTURE_DEPENDENCY → HOLD affected branch`。

## 10｜Work-item／Mirror／Duplicate Lifecycle

PR、Issue、Branch、Return、Candidate、Pending、ACK、TO_VERIFY 都是 work-item carrier／state，不是永久治理器官。

- OPEN／ACTIVE 必須仍有 Domain、Authority、Affected Scope、Evidence、Next Gate、Return Target。
- MERGED／CLOSED 只代表 Carrier Event；不等於 Current、Absorbed、Approved。
- CLOSED_UNMERGED 預設無 Current eligibility；只有 unique primitive／evidence／failure／lineage 保留 explicit re-entry value。
- SUPERSEDED 後，舊 merge order、READY／HOLD、review verdict、tool／agent assumption 失去 Current effect。

三倉與其他 Carrier 的重複處理：

```text
Stable Existence
→ Representation／Revision／Event Compare
→ Native／Projection／Mirror Role
→ Unique Delta／Evidence／Failure
→ Successor Coverage
→ Active Caller／Rebuild Dependency
→ Retention／Rights／Owner
→ PROVENANCE_ONLY／HOLD／RECLAIM_ELIGIBLE_CANDIDATE
```

Same SHA 不直接授權刪除；Git history 優先承載 provenance，不另造活文件複製歷史。

## 11｜Failure Geometry／Error Containment

Failure 可判為：

- `TRUE_GATE`
- `REPRESENTATION_MISMATCH`
- `APPROACH_MISALIGNMENT`
- `THRESHOLD_FRICTION`
- `SCALE_MISMATCH`
- `CARRIER_ARTIFACT`
- `WRONG_ENTRY`

同一路徑重試但 material variable 未變：`PROCESS_THRASH`。

錯誤依 WORLD／MODEL／REPRESENTATION／CARRIER／AUTHORITY／EVIDENCE／READER 定位，只 invalidate affected cone。退一步、換 representation、換 Carrier、合法 HOLD 都是正式 Action。

## 12｜CoreTri／七窗／Shared Boundary

CoreTri Native Authority 只屬 Ideas／DCP／GLModel：

- Ideas：Meaning／Placement／Memory／Architecture。
- DCP：Dependency／Contract／State／Authority／Admission／Return／Rebuild／Metabolism。
- GLModel：World／Object／Relation／Projection／Engineering／Reconstruction。

外參、實驗、實證、造返是橫向與回饋作用面，不形成第四 Native Pole。

Shared Belt 只承載 Pointer、Wake、Receipt、Receiver State、Return、Conflict、Re-entry／Rebuild pointer；不保存 Native Body、不形成 Common Current 或 Central Truth。

跨窗固定：

```text
Delta → Affected Cone → Receiver Wake → Local Rebuild／Execute → Material Return
```

沒有 Material Delta：`NO_DELTA → Stay Local`。

## 13｜Re-entry／Rebuild Gate

Historical searchable 不等於 Wake eligible。Legacy 只能在 conflict、audit、missing lineage、unique failure/evidence、resurrection review 或 explicit rebuild trigger 下 bounded re-entry。

```text
Material Trigger
→ Exact Family／Artifact Pointer
→ Source／Rights／Owner Gate
→ Bounded Primitive／Evidence／Failure Read
→ Successor Comparison
→ Receiver-native Disposition
→ Reconciliation／Rebuild or NO_REBUILD_WITH_REASON
```

Whole-body reread、startup-text dependence、固定 Carrier topology 與 stale registry pointer 都不得自行重建 Current。

## 14｜Current Reader Surface

正常 Reader 只需：

1. `README.md`
2. `CURRENT-SURFACE-MANIFEST.json`
3. `LIFECYCLE_DEPENDENCY_CHAIN_KERNEL.md`
4. `PUBLIC-SURFACE-POLICY.md`
5. `STATUS.md`

Legacy files 只作 lineage／failure／explicit re-entry。新格式、新工具或新 Carrier 可加入，不因其副檔名或平台另建 ontology family。

## Professional English

The kernel is existence-first and carrier-neutral. Stable identity, dependency, lifecycle state, authority, evidence and claim ceilings, action effects, receiver-owned return closure, reconciliation, rebuild and metabolism are primary. Source intake and recomposition require qualification, rights, compatibility and fidelity. Security is default-deny for instruction authority, inbound commands, credentials and external writeback. Temporal lineage separates state-changing events from records, copies and replays. Agent-like or long-running work requires an explicit execution-resource envelope covering tool scope, budget, retry and concurrency limits, stop conditions, verification, rollback, human escalation and return. Historical bodies may re-enter only through exact affected-scope triggers; they cannot reconstruct Current by searchability alone.
